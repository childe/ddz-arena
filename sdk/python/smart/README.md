# 智能 bot（三人斗地主 / 四人斗地主 / 掼蛋）

基于规则的智能 bot：拆牌、记牌、炸弹管理、叫分和队友配合。线上服务器用它们给玩家补位（房间里的「智能 bot 补位」按钮，见接口文档 7.3 节）；你也可以自己运行，拉进任意房间。命令都在 `sdk/python` 目录下执行，依赖与 SDK 相同（`websocket-client`）。

| 文件 | 用途 |
|---|---|
| `smart3_bot.py` | 三人斗地主 bot `Smart3Bot` |
| `smart4_bot.py` | 四人斗地主 bot `Smart4Bot` |
| `smart_gd_bot.py` | 掼蛋 bot `SmartGuandanBot` |
| `join.py` | 把智能 bot 拉进一个已有房间，按房间类型自动选 smart3、smart4 或 smart_gd |
| `table.py` | `examples/run_table.py` 加上 `smart3` / `smart4` / `smart_gd`，注册一组新 bot 开一桌打 K 局 |
| `service.py` | 服务器上的补位服务（systemd 服务 `ddz-bots`）：每种游戏 4 个 bot，按玩家的邀请入座 |
| `ddz3_sim.py` / `ddz4_sim.py` / `gd_sim.py` | 不连服务端的本地模拟器，带复式对局评估，用来调参 |

测试在 `tests/test_smart3.py`、`test_smart4.py`、`test_smart_gd.py`，随 SDK 测试一起运行。

## 常用命令

```bash
# 往房间里拉 2 个智能 bot 并准备，Ctrl+C 让它们离开
python smart/join.py --room r_xxxxxx --count 2
# 掼蛋评估：smart_gd 对 greedy 打 500 副牌
python smart/gd_sim.py --deals 500
# 新开一桌：4 个 smart4 打 100 局，每步停 1.5 秒
python smart/table.py --base https://ddz.ohmycat.me --game ddz4 --bots smart4 --games 100 --pause-ms 1500 --invite 邀请码
# 评估：smart3 对 greedy 打 1000 副牌
python smart/ddz3_sim.py --bot smart3 --baseline greedy --deals 1000
```

`join.py` 从固定的 bot 池（智能A 到 智能H）里挑当前不在别的房间的 bot，第一次用到某个名字时才注册，需要 `--invite`；token 保存在 `smart/tokens.json`（已在 `.gitignore` 里）。默认服务地址是 `https://ddz.ohmycat.me`，每步停 1.5 秒（`--pause-ms`）。这些名字在线上已经被注册，自己运行时请改用别的名字（修改 `join.py` 里的 `POOL`）。

## 策略

smart3 和 smart4 的思路相同，只是牌规和参数不同：

- 拆牌：把手牌拆成炸弹、顺子、连对、飞机、三带、对子、单张，取代价最低的拆法。牌越小的组代价越高，炸弹的代价为负。
- 记牌：全部牌减去自己的手牌和已出的牌，剩下的就是别人可能有的牌。一组牌如果别人没有能压住它的非炸弹组合，就算「必胜组」。
- 领出：除了必胜组只剩一组时，先出必胜组再走完；否则先出最小的弱组，长牌型优先。对手快出完时（四人 5 张、三人 2 张以内），改出对手接不住的牌。队友只剩 1 张时，送一张最小的单牌。
- 跟牌：从能压的出法里，挑拆完剩下的牌代价增加最少的一手；代价增加超过阈值就不出。对手快出完时不计代价。农民不压队友，除非压完自己就能走完。
- 三人特有：地主上家看到地主下家出 J 以下的单张或对子时，如果不伤自己的牌，就顶一手，逼地主出更大的牌。
- 炸弹：能走完时炸；对手快出完时炸；农民在地主剩一定张数以内时炸（四人 12 张、三人 10 张）；剩下的牌很好时也炸。都用能压住的最小炸弹。
- 叫分：按拆牌代价和大牌、炸弹数量算手牌强度，按门槛叫 3 / 2 / 1 分。四人的门槛是 6 / 4.5 / 2.5，三人是 0 / −1 / −2（两边的强度不是同一个尺度）。

## 评估结果

复式对局：同一副牌先由对照 bot 坐满打一遍，再让被测 bot 轮流坐到每个座位上各打一遍，用同一座位的得分差抵消发牌运气。

| 对比 | 局数 | 每局多赢的分数 | 只看输赢（地主 ±3 或 ±2，农民 ±1） |
|---|---|---|---|
| smart4 对 greedy（四人） | 2000 | 9.9 ± 1.6 | 0.47 ± 0.04 |
| smart3 对 greedy（三人） | 3000 | 1.36 ± 0.13 | 0.28 ± 0.03 |

## 掼蛋 bot

`SmartGuandanBot` 沿用同样的框架，按掼蛋规则改了这些：

- 拆牌：先拿出天王炸、炸弹和一个同花顺（不拆炸弹去凑同花顺），再找固定长度的顺子（5 张）、木板（3 连对）、钢板（2 连三张），剩下的组成三带二、三同张、对子、单张。每张逢人配试着补到有用的点数上（凑三张或炸弹、补顺子的空档），或者留作级牌，取代价最低的拆法。
- 队友配合：队友出的牌不压，除非压完自己就能走完。对手出牌时，如果队友在这一轮还有机会接，自己只在不伤牌型时才压；队友已经过了（或已出完）时更愿意压。队友只剩 1–2 张时送单张。
- 炸弹和危险：对手剩 9 张以内、或出牌的对手剩 6 张以内时全力压，可以用炸弹；剩下的牌够好时也炸。
- 还贡：还掉对拆牌伤害最小的那张。

评估用 `gd_sim.py`：同一副牌、同一级数、同一首出，被测 bot 先坐 0 队、再坐 1 队各打一局；每局的结果是头游一队 +升级数（3/2/1），另一队取负。不含进贡（进贡让各局互相依赖）。

| 对比 | 副数 | 每局多升的级数 | 拿到头游的比例 |
|---|---|---|---|
| smart_gd 对 greedy | 500（1000 局） | 1.61 ± 0.05 | 81% |
| smart_gd 对 random | 100（200 局） | 2.95 ± 0.03 | 99.5% |
