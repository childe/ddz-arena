# 智能 bot（三人斗地主 / 四人斗地主 / 掼蛋 / 拱猪）

基于规则的智能 bot：拆牌、记牌、炸弹管理、叫分和队友配合。线上服务器用它们给玩家补位（房间里的「智能 bot 补位」按钮，见接口文档 7.3 节）；你也可以自己运行，拉进任意房间。命令都在 `sdk/python` 目录下执行，依赖与 SDK 相同（`websocket-client`）。

| 文件 | 用途 |
|---|---|
| `smart3_bot.py` | 三人斗地主 bot `Smart3Bot` |
| `smart4_bot.py` | 四人斗地主 bot `Smart4Bot` |
| `smart_gd_bot.py` | 掼蛋 bot `SmartGuandanBot` |
| `smart_gz_bot.py` | 拱猪 bot `SmartGongzhuBot` |
| `join.py` | 把智能 bot 拉进一个已有房间，按房间类型自动选 smart3、smart4、smart_gd 或 smart_gz |
| `table.py` | `examples/run_table.py` 加上 `smart3` / `smart4` / `smart_gd` / `smart_gz`，注册一组新 bot 开一桌打 K 局 |
| `endgame.py` | 残局搜索，smart3 和 smart4 共用 |
| `pimc.py` | smart3 的中局推演 |
| `ddz3_bidfit.py` | 用模拟对局拟合 smart3 叫分用的地主胜率模型 |
| `service.py` | 服务器上的补位服务（systemd 服务 `ddz-bots`）：每种游戏 4 个 bot，按玩家的邀请入座 |
| `ddz3_sim.py` / `ddz4_sim.py` / `gd_sim.py` / `gz_sim.py` | 不连服务端的本地模拟器，带复式对局评估，用来调参 |

测试在 `tests/test_smart3.py`、`test_smart4.py`、`test_smart_gd.py`、`test_smart_gz.py`，随 SDK 测试一起运行。

## 常用命令

```bash
# 往房间里拉 2 个智能 bot 并准备，Ctrl+C 让它们离开
python smart/join.py --room r_xxxxxx --count 2
# 掼蛋评估：smart_gd 对 greedy 打 500 副牌
python smart/gd_sim.py --deals 500
# 拱猪评估：smart_gz 对 greedy 打 200 副牌，7 个进程并行
python smart/gz_sim.py --deals 200 --jobs 7
# 新开一桌：4 个 smart4 打 100 局，每步停 1.5 秒
python smart/table.py --base https://ddz.ohmycat.me --game ddz4 --bots smart4 --games 100 --pause-ms 1500 --invite 邀请码
# 评估：smart3 对 greedy 打 1000 副牌
python smart/ddz3_sim.py --bot smart3 --baseline greedy --deals 1000
```

`join.py` 从固定的 bot 池（智能A 到 智能H）里挑当前不在别的房间的 bot，第一次用到某个名字时才注册，需要 `--invite`；token 保存在 `smart/tokens.json`（已在 `.gitignore` 里）。默认服务地址是 `https://ddz.ohmycat.me`，每步停 1.5 秒（`--pause-ms`）。这些名字在线上已经被注册，自己运行时请改用别的名字（修改 `join.py` 里的 `POOL`）。

## 策略

smart3 和 smart4 的思路相同，只是牌规和参数不同：

- 拆牌：把手牌拆成炸弹、顺子、连对、飞机、三带、对子、单张，取代价最低的拆法。牌越小的组代价越高，炸弹的代价为负。
- 记牌：全部牌减去自己的手牌和已出的牌，剩下的就是别人可能有的牌。一组牌如果别人没有能压住它的非炸弹组合，就算「必胜组」。
- 领出：除了必胜组只剩一组时，先出必胜组再走完；否则先出最小的弱组，长牌型优先。对手快出完时（四人 5 张、三人 2 张以内），先出张数比对手剩余牌还多的牌型；没有的话，把大牌留着以后抢回出牌权，先出张数比对手剩余牌少的小牌（对手管上了也走不完，还可能被迫拆牌），再考虑张数正好等于对手剩余牌的；同一档里出最不容易被管上的（按剩下的牌估算概率）。队友只剩 1 张时，送一张最小的单牌。
- 跟牌：从能压的出法里，挑拆完剩下的牌代价增加最少的一手；代价增加超过阈值就不出。对手快出完时不计代价。农民不压队友，除非压完自己就能走完。
- 三人特有：地主上家看到地主下家出 J 以下的单张或对子时，如果不伤自己的牌，就顶一手，逼地主出更大的牌。
- 炸弹：能走完时炸；对手快出完时炸；农民在地主剩一定张数以内时炸（四人 12 张、三人 10 张）；剩下的牌很好时也炸。都用能压住的最小炸弹。
- 残局搜索：所有人手里合计不超过 20 张（四人 32 张）、且有人剩 5 张以内时，不再按规则出牌：把没见过的牌随机分给其他人（地主还没出的底牌固定在地主手里），每种分法都推演到底，算出每种出法能不能赢，出赢得最多的那手；和规则出法一样多时按规则出。每步最多抽 24 种分法、算 2 秒，超时就按规则出。可选的对手牌推断（`ENDGAME_PASS_WEIGHT` < 1）会少抽「对手能管却过了」的分法，实测在残局里没有提升，默认关闭。
- 叫分：按拆牌代价和大牌、炸弹数量算手牌强度，按门槛叫 3 / 2 / 1 分。四人的门槛是 6 / 4.5 / 2.5。
- 三人叫分看胜率：用拆牌代价、组数、大小王、2、A、K、炸弹和王炸 9 个特征估算这手牌当地主的胜率（逻辑回归，`ddz3_bidfit.py` 用 6 万局模拟拟合），胜率到 55% / 45% / 35% 叫 3 / 2 / 1 分；前面有人叫过分时门槛各加 10%（叫分的人牌好，我们当地主更难赢）。旧的强度门槛（0 / −1 / −2）还用来推断对手的牌。
- 三人中局推演：残局搜索之前的每一步，把没见过的牌随机分给另外两家，抽 48 种分法，按对手的叫分和这种分法给对手的牌是否相符加权，按权重留 32 种。每种分法上把最多 6 种候选出法（规则出法、过、代价最低的几手、最小的炸弹）各推演到底（推演时所有人按规则出牌），只看输赢，出赢得最多的那手；比规则出法平均多赢不到 0.1 时按规则出。每步最多算 1.5 秒，超时按规则出。

## 评估结果

复式对局：同一副牌先由对照 bot 坐满打一遍，再让被测 bot 轮流坐到每个座位上各打一遍，用同一座位的得分差抵消发牌运气。

| 对比 | 局数 | 每局多赢的分数 | 只看输赢（地主 ±3 或 ±2，农民 ±1） |
|---|---|---|---|
| smart4 对 greedy（四人） | 2000 | 9.9 ± 1.6 | 0.47 ± 0.04 |
| smart3 对 greedy（三人） | 3000 | 1.36 ± 0.13 | 0.28 ± 0.03 |
| smart3 对只按规则出牌的旧版 smart3 | 3000 | 0.71 ± 0.12 | 0.20 ± 0.03 |

最后一行是加上叫分看胜率和中局推演之后的版本，对比旧版（旧叫分门槛、只有残局搜索）。只开叫分看胜率时每局多赢 0.19 ± 0.05 分。两条规则（队友剩 2 张时送对子、优先出对手都过过的牌型）测下来没有提升，没有采用。smart3 对 greedy 一行是加推演之前测的。

残局搜索的效果：在模拟对局的残局里，用全部手牌求出的最优解核对 bot 的选择，只统计选对选错会影响输赢的决策（三人 600 局中 191 次，四人 600 局中 121 次）。三人斗地主规则出法选对 94.2%，残局搜索 99.5%；四人斗地主规则出法 90.9%，残局搜索 97.5%。这类决策每局不到一次，所以对整体胜率的提升很小。

## 掼蛋 bot

`SmartGuandanBot` 沿用同样的框架，按掼蛋规则改了这些：

- 拆牌：先拿出天王炸、炸弹和一个同花顺（不拆炸弹去凑同花顺），再找固定长度的顺子（5 张）、木板（3 连对）、钢板（2 连三张），剩下的组成三带二、三同张、对子、单张。每张逢人配试着补到有用的点数上（凑三张或炸弹、补顺子的空档），或者留作级牌，取代价最低的拆法。
- 队友配合：队友出的牌不压，除非压完自己就能走完。对手出牌时，如果队友在这一轮还有机会接，自己只在不伤牌型时才压；队友已经过了（或已出完）时更愿意压。队友只剩 1–2 张时送单张。
- 炸弹和危险：对手剩 9 张以内、或出牌的对手剩 6 张以内时全力压，可以用炸弹；剩下的牌够好时也炸。
- 还贡：还掉对拆牌伤害最小的那张。

评估用 `gd_sim.py`：同一副牌、同一级数、同一首出，被测 bot 先坐 0 队、再坐 1 队各打一局；每局的结果是头游一队 +升级数（3/2/1），另一队取负。不含进贡（进贡让各局互相依赖）。

| 对比 | 副数 | 每局多升的级数 | 拿到头游的比例 |
|---|---|---|---|
| smart_gd 对 greedy | 500（1000 局） | 1.61 ± 0.05 | 81% |
| smart_gd 对 random | 100（200 局） | 2.95 ± 0.03 | 99.5% |

## 拱猪 bot

`SmartGongzhuBot` 不用拆牌框架，出牌用蒙特卡洛模拟：

- 候选牌：所有可出的牌。同一花色里相邻的两张（中间没有别人可能有的牌）分值又相同时，出哪张效果一样，只算一张。
- 发牌：把没见过的牌随机分给其他三家，和已知信息一致：每家剩几张、每家已经缺的花色（没跟领出的花色）、亮出还没出的牌在亮牌人手里。
- 推演：每种发法下，每张候选牌都打到这一局结束，四家后面都按贪心策略出牌（领出最短花色里最小的非分牌；跟牌把猪塞给 `AS` / `KS`，能躲就躲在当前最大牌下面；垫牌先垫猪，再垫最贵的红桃，猪还没出时再垫 `AS` / `KS`）。所有候选牌用同一批发法。
- 选择：出平均平台分 `(4 × 自己得分 − 四人得分之和) / 10` 最高的牌。每步最多算 0.35 秒或 300 种发法（`budget`、`max_samples` 可调），实测每步 0.3 秒以内。
- 亮牌按规则：猪只在手里有 5 张以上比 Q 小的黑桃、且没有 `AS` / `KS` 时亮；羊在方块 4 张以上、且有 `AD` `KD` `QD` 中两张时亮；变压器不亮（它把收到它的人的得分翻倍，通常是负分）；`AH` 只在红桃 9 张以上且有 `KH` 时亮（争全红）。

评估用 `gz_sim.py`：同一副牌先由 4 个对照 bot 打一遍，再让被测 bot 轮流坐到每个座位上（其余 3 家是对照 bot）各打一遍，比较同一座位的平台分。每局都是一场比赛的第一局（持 `2C` 的人先出）。

| 对比 | 副数 | 每局多得的平台分 | 收到猪的比例（对照 bot 在同一座位） |
|---|---|---|---|
| smart_gz 对 greedy | 300 | 32.5 ± 1.4 | 18.7%（25.0%） |
| smart_gz 对 random | 100 | 32.7 ± 1.7 | 7.5%（25.0%） |
| greedy 对 random | 300 | 17.8 ± 0.9 | 9.7%（25.0%） |
