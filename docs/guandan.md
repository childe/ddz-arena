# 掼蛋设计

用户已确认（2026-11-16）：完整规则（级牌、逢人配、同花顺、进贡还贡与抗贡、按名次升级、一场打到过 A）。本文是引擎、服务端、网页和 SDK 的共同依据。

## 1. 座位、牌和牌值

- 4 个座位，`game: "guandan"`。座位 0、2 是 0 队，座位 1、3 是 1 队，对家是队友。出牌顺序 0 → 1 → 2 → 3 → 0，已出完的座位跳过。
- 两副牌 108 张，每人 27 张，没有底牌，不叫分。编码与四人斗地主相同：`rank + suit`，rank 为 `23456789TJQKA`，suit 为 `SHCD`，王为 `BJ`（小王）、`RJ`（大王）；同一编码最多 2 张，手牌与出牌按多重集合处理。
- **级牌**：本局的级数 `level` 是 `2`…`A` 中的一个点数。
- **单张牌值**（用于单张、对子、三张、三带二、炸弹的比较）：`2 < 3 < … < K < A`，其中级牌点数被抽出来放到 A 之上，再往上是小王、大王。例：打 7 时 `… 6 < 8 < … < A < 7 < BJ < RJ`。打 2 时 `3 < … < A < 2 < BJ < RJ`。
- **顺序值**（用于顺子、木板、钢板、同花顺）：按自然顺序 `A(低) 2 3 … K A(高)`，级牌在自然位置，王不能参与。A 可以当最小（`A2345`、`AA2233`、`AAA222`）或最大（`TJQKA`、`QQKKAA`、`KKKAAA`），不能绕圈（`QKA23` 非法）。
- **逢人配**：红桃级牌（如打 7 时的 `7H`，共 2 张）可以当作除大小王之外的任意一张牌使用。单独出或与同点数一起出时就是级牌本身。

## 2. 牌型

| `type` | 名称 | 构成 | `rank`（比较用） |
|---|---|---|---|
| `single` | 单张 | 1 张 | 牌值 |
| `pair` | 对子 | 同点数 2 张（`BJ BJ`、`RJ RJ` 是对子，`BJ RJ` 不是） | 牌值 |
| `triple` | 三同张 | 同点数 3 张（王不能） | 牌值 |
| `triple_pair` | 三带二 | 三同张 + 一个对子（对子可以是 `BJ BJ`/`RJ RJ`；对子点数与三张不同） | 三张的牌值 |
| `straight` | 顺子 | 恰好 5 张连续点数，不能有王 | 最大一张的顺序值（`A2345` 为 5，`TJQKA` 为 A） |
| `pair_chain` | 木板（三连对） | 恰好 3 个连续对子 | 最大对子的顺序值 |
| `plane` | 钢板 | 恰好 2 个连续三张 | 较大三张的顺序值 |
| `bomb` | 炸弹 | 同点数 4–8 张（王不能），`length` = 张数 | 牌值 |
| `straight_flush` | 同花顺 | 同花色的 5 张顺子 | 同顺子 |
| `rocket` | 天王炸 | 4 张王 | — |

- 非炸弹牌型只能被同类型、`rank` 更大的牌压。
- 炸弹类从小到大：4 张炸弹 < 5 张炸弹 < 同花顺 < 6 张炸弹 < 7 张炸弹 < 8 张炸弹 < 天王炸。同类比 `rank`。炸弹类可以压任何非炸弹牌型。
- 逢人配可以补进任何牌型（包括炸弹和同花顺），但不能当王；天王炸只能是 4 张真王。
- API 中的 `pattern` 为 `{"type", "rank", "length"}`：`rank` 是点数标签（`"2"`…`"A"`、`"BJ"`、`"RJ"`），顺子类为最大一张的点数（`A2345` 的 `rank` 为 `"5"`）；`length` 对 `bomb` 是张数，其余为 1（天王炸为 4）。
- **出牌解析**：同一组牌可能有多种解释（如含逢人配的 `3 4 5 6 7H(打7)` 可以是 `34567` 或 `23456` 的顺子）。请求可以带 `pattern: {"type", "rank"?}` 指定；不带时，跟牌选能压过上家的解释中最小的一个，领出选优先级最高的解释：炸弹类（越大越优先）> 其他（`rank` 越大越优先）。指定的解释不成立时返回 422 `PATTERN_MISMATCH`。

## 3. 一局的流程

1. **发牌**：洗牌后每人 27 张。
2. **进贡**（一场的第一局没有）：按上一局的名次（`order`，头游在前）。
   - 单下（末游的队友不是三游）：末游向头游进贡。
   - 双下（三游、末游同队）：三游、末游都进贡；较大的贡牌给头游，较小的给二游；牌值相同时，头游下家方向先遇到的进贡者给头游。
   - 贡牌由服务端自动选择：手中牌值最大的一张，逢人配除外；同牌值多张时取花色顺序 `S H C D` 中最前的一张。贡牌公开。
   - **抗贡**：单下时末游手里有 2 张大王，或双下时两个进贡者合计有 2 张大王，则不进贡也不还贡。
3. **还贡**：每个收贡者从自己手中选一张自然点数 2–10 的牌（不能是王，不能是逢人配）还给对应的进贡者。双下时头游先还、二游后还。还的牌公开。
4. **首出**：第一局随机座位先出。之后：有进贡时，进贡者先出（双下时给头游进贡的那位先出）；抗贡时上一局的头游先出。
5. **出牌**：与斗地主相同，领出者任意出，其余人压或过。所有仍在场的其他人都过后，最后出牌的人重新领出。
   - 有人出完最后一张牌后，按出完顺序记为头游、二游、三游。
   - **接风**：如果出完牌的人最后那手牌没人压（其余在场的人都过），由他的队友领出；队友也已出完时由下一个在场的人领出。
6. **结束**：一队两人都出完，或三人出完时，本局结束。名次 `order` 补齐（还在场的人按座位顺序从出完者的下家开始排在后面）。

## 4. 升级与一场比赛

- 两队各有自己的级数，开场都是 `2`。本局的级数 = 「主打队」（上一局升级的队；第一局为 0 队）的级数。
- 头游所在的队升级：队友二游升 3 级，三游升 2 级，末游升 1 级。级数最高到 A，不会超过。升级的队成为下一局的主打队。
- **过 A**：主打队级数为 A 的一局，如果主打队拿到头游且队友不是末游，这一队赢下这场比赛（`match_winner`）。下一局两队都重置为 `2`，第一局规则（无进贡、随机首出）重新开始。
- **A 打三次不过退回 2**：主打队在 A 打了 3 局都没有过 A（每次以主打队身份打 A 级、没赢下比赛算一次），该队级数退回 `2`，次数清零。
- **平台计分**（`scores`，用于排行榜）：头游队两人各 `+升级数`，另一队两人各 `-升级数`。赢下比赛的那局额外 ±3。四人之和为 0。

### 规则澄清（引擎实现时补充）

- 只由逢人配组成的出牌（1 或 2 张）就是级牌本身：打 7 时 `7H 7H` 只能是一对 7。
- 炸弹最多 8 张：同点数 9–10 张（8 张自然牌 + 逢人配）不是合法牌型，需要拆开出。
- 领出时多个非炸弹解释的 `rank` 相同，按第 2 节表格中 `type` 的顺序取靠前的一个。
- 还贡的「自然点数 2–10」包含非红桃的级牌；收贡者手里没有 2–10 的牌时，可以还逢人配以外的任意一张。
- A 打三次的计数在升级之后结算：第三次没过 A 时，即使主打队拿到头游（队友末游）也退回 `2`。
- 过 A 那一局的结果里 `team_levels_after` 为 `["2","2"]`、`level_team_next` 为 0、`a_attempts` 为 `[0,0]`；新一场的 `hand_no` 从 1 重新计数。
- `game.finished` 中的 `a_attempts` 是本局结算后的次数。第 5 节示例的 `scores` 原为 `[4,-4,4,-4]`，与计分规则（升级 3 → ±3）不符，已改为 `[3,-3,3,-3]`。

## 5. 接口

在通用接口之上：

| 方法 | 路径 / WS op | 请求体 | 说明 |
|---|---|---|---|
| POST | `/games/{gid}/play` / `play` | `{"cards":[...], "pattern"?:{"type","rank"?}, "seq"?}` | 出牌；`cards: []` 为过 |
| POST | `/games/{gid}/return` / `return` | `{"card":"5S", "seq"?}` | 还贡 |
| GET | `/games/{gid}/legal-moves` | — | 出牌阶段 `{"moves":[{"cards","pattern"}],"can_pass"}`；还贡阶段 `{"return_cards":[...]}`（可还的不同牌） |

房间配置：`play_timeout_ms`（默认 20000，出牌和还贡共用）、`legal_moves_api`、`auto_restart`。

超时代打：还贡还最小的一张可还牌；出牌时能过就过，领出时出牌值最小的单张（不出逢人配，除非只剩逢人配）。

### 事件

- `game.started`：`{"game":"guandan","players","hand_no","level":"7","level_team":1,"team_levels":["2","7"],"a_attempts":[0,0],"cards_left":[27,27,27,27]}`，私有字段 `hand`（已经扣掉贡牌、加上收到的贡牌之前的原始 27 张）。
- `tribute`：`{"anti":false,"tributes":[{"from":3,"to":0,"card":"RJ"}]}`；抗贡时 `{"anti":true,"tributes":[]}`。紧跟在 `game.started` 后面（第一局没有）。贡牌在这个事件里已经转到收贡者手中。
- `turn`：`{"seat","phase":"return"|"playing","to_beat","can_pass"}`。
- `returned`：`{"from":0,"to":3,"card":"5S"}`。
- `played`：`{"seat","cards","pattern","cards_left"}`；`passed`：`{"seat"}`。
- `player.out`：`{"seat","place"}`（place 1–3，紧跟在该玩家最后一手 `played` 之后）。
- `game.finished`：`{"result":{"order":[2,0,1,3],"winner_team":0,"upgrade":3,"level":"7","team_levels_before":["5","7"],"team_levels_after":["8","7"],"level_team_next":0,"a_attempts":[0,0],"match_winner":null,"scores":[3,-3,3,-3]},"seed"}`。

### 视图

- `GET /games/{gid}`：`game`、`phase`（`return`/`playing`/`finished`）、`hand_no`、`level`、`level_team`、`team_levels`、`a_attempts`、`tribute`（`{"anti","tributes"}` 或 null）、`returns`（`[{"from","to","card"}]`）、`turn`、`to_beat`、`can_pass`、`cards_left`、`order`（已出完的座位）、`history`、`result`。
- `GET /games/{gid}/state`：再加 `seat`、`hand`，轮到自己时加 `legal`。
- 回放：`initial_hands`（发牌后、进贡前的 27 张）和 `seed`。
